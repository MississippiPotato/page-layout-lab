# 页面布局实战课 · Page Layout Studio

一个中英双语的教学网站，讲**如何做好页面布局**。五章沿用同一个 Campus Pulse
数据看板，从一份混乱初稿开始，依次完成诊断、栅格、空间分组、响应式与最终审计。

这不是 Flex / Grid / 媒体查询的语法手册。课程要回答的是：
**为什么这样布局、依据是什么、改完之后哪一项指标真的变了。**

---

## 这门课的三个立论

### 1. 页面布局和图表布局是同一套数学

`d3.scaleBand()` 的 `paddingInner` **就是**栅格的 gutter，`step()` 就是列距，
`bandwidth()` 就是列宽；Bostock 的 margin convention **就是**容器的 padding。
页面栅格不需要另一套数学——它本来就是一维 band scale。

这条线贯穿全课，代码上由 [`dist/js/charts.js`](dist/js/charts.js) 的
`gridBand()` 与 `plotArea()` 承担，第 2 章明讲，其余各章复用。

### 2. 布局的后果必须可观测，不能只是评分

看板里的六个模块都是**真实的 D3 图表**，读真实数据，并各自声明**硬约束**：

| 模块 | 图表 | 硬约束（可实测） |
| --- | --- | --- |
| 每周活跃趋势 | `d3.line` + `d3.area` | 12 个周标签不重叠（由就地实测判定） |
| 学习时段热力图 | `scaleBand` × 2 + `scaleSequential` | 单元格边长 ≥ 8px |
| 课程完成率排行 | 排序横向条形 + `scaleBand` | 行高 ≥ 22px（8 门课 ⇒ 高度 ≥ 223px） |
| 平均完成率 | `d3.arc` 环形 | 宽高比 1:1，直径 ≥ 90px |
| 设备分布 | `d3.stack` | 图例必须排得下（身份不可只靠颜色） |
| 看板说明 | 实测断行文本 | 每行 45–75 西文字符 / 22–38 汉字 |

把栏宽调窄，后果不是"扣 12 分"，而是坐标轴标签**真的**重叠、热力图单元格
**真的**糊掉。所有指标都来自浏览器实测（`getBBox()` /
`getComputedTextLength()` / `getBoundingClientRect()`），不是手调常数。

一个反复踩到的坑记在这里：**字宽依赖最终真正落到哪个字体**，同一个「1周」
在不同文档里量到 21.1px 与 29.4px。所以任何"按字宽推出来的常数"都不可信，
判定必须交给就地实测；演示也统一等 `document.fonts.ready` 之后再渲染，
否则量到的是回退字体的尺寸。

体检卡刻意**不合成单一总分**：五个指标量纲不同（个 / px / 字符），
加权相加只会得到一个没有含义的数字。它逐项呈现，并指出下一步该修哪一项。

### 3. 主线是机制的，不只是叙事的

前四章的产出都写进 `localStorage`，第 5 章直接拿来用：

```
第 1-1 节  限时任务 A ──→ baseline（用时 / 误点 / 点击轨迹）
第 1-2 节  优先级矩阵 ──→ priority[]  ──→ 第 4-2 节的窄屏排序直接读它
第 2 章    栅格参数   ──→ grid        ──→ 第 5 章的目标版面按它生成
第 5-2 节  拖拽实验室 ──→ layout      ──→ 第 5-3 节审计的就是它
第 5-4 节  限时任务 B ──→ 与第 1-1 节的 baseline 并排对照
```

第 1 章的乱稿里，排行榜按教务系统的**录入顺序**显示、且不高亮最低项，
所以"找出完成率最低的课程"必须逐行读完 8 个数字；重构后按完成率排序并标红，
同一道题变成"看最后一行"。两次用时之差就是布局价值的证据。

> **必须同时说明**：这是 n=1、非受控的一次自测，第二次还带练习效应。
> 它演示的是"布局影响视觉搜索"这一机制，**不是实验结论**。
> 这句话在界面上始终可见，不允许折叠隐藏。

## 四个特色

**限时任务实验**　学习者亲自在乱稿上计时作答，用时、误点与点击轨迹被记录，
重构后用同一道题复测。

**关键代码取自运行中的源码**　「关键代码」标签页不是手写副本：
[`dist/js/snippets.js`](dist/js/snippets.js) 在运行时 `fetch` 模块自身，
按 `// #region snippet:<名字>` 标记截取，并标注真实行号（如 `charts.js · L66–85`）。
因此代码页永远等于实现，不存在"忘记同步"这种失败模式——
旧版手写的 40 段代码里，有多处声称用了 `d3.scaleBand()` / `d3.group()`，
而实现里根本没调用过。

**Layout X-Ray，并且敢审视本站自己**　顶栏常驻「审视本站」按钮，
用 `getBoundingClientRect()` 透视**这个教学网站自己**的列线、基线与触控目标。
它第一次运行就查出本站有 7 个可点元素高度只有 39–43px，低于课程第 4-3 节讲的
WCAG 44×44px——已按查出的结果修正，现在复检为 0。

**判分由实测决定的小测**　第 3-4 节让学习者先凭直觉在三种页面组成里选一个，
再摊开三者的实测结果。答案不是预设的：违反数、首屏可见模块数与任务扫视距离
都是当场算出来的。

## 课程结构

两层信息架构：课程门户 → 5 个章节；每章 4 个小节，每节固定三部分
**📖 讲解 / ⌨️ 关键代码 / ▶️ 演示**。

| 章节 | 主题 | 演示原型 |
| --- | --- | --- |
| 01 | 先诊断，再布局 | 真实看板 + 标注叠层 + 计时/点击轨迹 |
| 02 | 网格、对齐与比例 | `scaleBand` 栅格 + 吸附 + 实测标尺 |
| 03 | 空间分组与页面组成 | `forceSimulation`（含自写矩形碰撞力） |
| 04 | 响应式与可访问布局 | 可调真实视口 + 并排对照 + 断点扫描 |
| 05 | Campus Pulse 综合重构 | 实测审计 + 任务复测 |

每章用各自的演示原型与画布形态，避免二十个演示长成一个样子。

## 本地运行

纯静态站点，无需安装依赖。**必须通过 http 服务器打开**——
「关键代码」要 `fetch` 源码，ES modules 也受同源策略限制。

```powershell
python -m http.server 4173 --directory dist
```

然后访问 <http://127.0.0.1:4173/>。

D3 v7.9.0 已随仓库附带（`dist/vendor/`），**断网也能完整运行**。

## 理论线索

- Gestalt：接近、共同区域、相似性
- Edward Tufte：视觉层级与信息密度
- Stephen Few：看板信息设计
- W3C WCAG 1.4.4 / 2.5.5：文字缩放、重排、触控目标
- Mike Bostock / D3：margin convention、scale、data join、transition、force

课程中所有经验阈值（面积比 2.5×、间距比 1.5×、覆盖率 38–72%）都在界面上
标明是**启发式**；与之相对，所有**实测量**（碰撞数、行高、每行字符数、
对齐误差、断点）都可以复算。两者不混为一谈。
